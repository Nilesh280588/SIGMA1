───────────────────────────────────────────────────────────────────────────────
 1. VISION — WHY THIS IS NOT A DASHBOARD
───────────────────────────────────────────────────────────────────────────────
Classic pharma dashboards show WHAT happened (graphs, KPIs). A pharma company
does not earn money from graphs — it earns from DECISIONS and ACTIONS taken on
time: finding the undiagnosed patient, restarting the discontinued therapy,
recovering the denied claim, moving marketing money to the state where it works.

This project therefore has three layers on every screen:

   LAYER 1 — SEE       : live analytics from the SSMS database (charts, KPIs),
                         now with Power-BI-style interactivity (see §4.0)
   LAYER 2 — UNDERSTAND: Claude reads the SAME live data (including the user's
                         active filters) and explains what it means for the
                         business (insight, risk, $ opportunity)
   LAYER 3 — ACT       : Claude proposes 2–3 alternative concrete actions
                         (patient-level AND business-level). A human approves →
                         the system EXECUTES the action (appointment,
                         notification/email, test order, internal task) and
                         audit-logs everything.

Guiding principles implemented everywhere:
  • NOTHING is hard-coded — no fake insights, no fixed numbers, no embedded API
    key. Every number is computed live from the DB, every insight is generated
    by the Claude model at runtime, every credential comes from .env.
  • HUMAN-IN-THE-LOOP — the AI can only PROPOSE; execution requires approval
    (except explicitly LOW-risk actions under Autonomous Mode — see §8A).
  • PRIVACY BY DESIGN — patient identity = patient_id ONLY (no name columns
    exist in the data). Physician names ARE used (commercial targeting).
  • AUDIT EVERYTHING — every proposal, approval, rejection, execution and
    notification is written to an audit log. ALL timestamps are stored and
    displayed in UTC (SYSUTCDATETIME), labeled "(UTC)" in the UI.
  • PLAIN LANGUAGE — every chart carries a caption a non-medical business
    reader understands; the AI is instructed to explain jargon inline.
  • SEIZURE-FIRST — SIGMA has "Seizure" in its name for a reason. Every number
    on every page is scoped to the seizure/epilepsy cohort (never a general
    population), and the AI is instructed (system prompt) to frame every
    headline, insight and recommendation around seizure patients FIRST, then
    the business/physician action that follows.

 FILE-BY-FILE, WHAT AND WHY:

 config.py
   WHAT: tiny .env loader (no external dependency): ANTHROPIC_API_KEY,
         CLAUDE_MODEL, DB_SERVER, DB_NAME, DB_TRUSTED_CONNECTION,
         DB_USERNAME/PASSWORD, SMTP_*.
   WHY : one switch point — rotating the key or repointing the DB is a .env
         edit, never a code change.

 db.py
   WHAT: pyodbc connection factory (tries ODBC Driver 18 → 17 → legacy);
         run_query()/execute()/scalar(); T-SQL helpers; ensure_agent_tables()
         auto-creates the 6 agent-operational tables; audit(); save/load_chat.
         sql_now() = SYSUTCDATETIME() — every operational timestamp is UTC,
         written EXPLICITLY on each insert (not left to column defaults).
   WHY : SSMS is the single source of truth; anything added in SSMS appears in
         the app on refresh. UTC guarantees consistent timestamps regardless
         of server timezone or who (human/agent) performed the action.

 backend.py
   WHAT: all page analytics as parameterised T-SQL (KPIs, funnel, delays,
         suspects, untreated, payer denials, switch flow, geo, physician
         performance, manufacturer mix). EVERY function accepts optional
         (d1, d2) date bounds — this is what makes the per-section date
         slicers filter every chart. get_date_bounds() feeds the sliders.
         OUR_MFR = 'EISAI' drives all "our company" logic.
   WHY : deterministic, fast, testable queries; the AI layers consume the
         OUTPUT of these queries so insights are grounded in exactly what the
         user currently sees (filters included).

 ai_engine.py
   WHAT: Claude client; INSIGHT_SCHEMA (strict JSON schema for opportunity
         cards); generate_page_insight(page, live_data) → validated JSON.
         System prompt carries the EISAI identity, the plain-language rule,
         the privacy rule, and the SEIZURE-FIRST rule (lead every response
         with seizure-patient impact, say "seizure patients"/"anti-seizure
         medicines" explicitly, then suggest the action). agent.py inherits
         this prompt, so the chat agent follows the same rule.
   WHY : structured outputs (json_schema) guarantee the model's answer is
         machine-executable — each option carries action_type + targets, so a
         click can execute it. No fragile text parsing.

 agent.py
   WHAT: the conversational tool-use agent. Tools: query_database (SELECT-only,
         write/DDL keyword blocklist, 200-row cap), propose_action
         (patient-level), propose_business_action (company-level). Manual
         agentic loop (up to 12 steps). The schema prompt describes all 18
         real tables (space-named, [bracketed]) and the epilepsy cohort
         definitions. run_autopilot_scan() = one "sweep everything" mission.
         Chat history persists in Agent_Chat_History across restarts.
   WHY : tool use lets Claude decide WHAT data it needs and fetch it itself.
         The manual loop is deliberate: it gates every side-effecting call,
         counts proposals, and enforces the read-only SQL policy.

 actions.py
   WHAT: the "hands". Patient executors (schedule_appointment,
         send_notification, order_diagnostic_test, change_prescription,
         escalate_claim, enroll_support_program, refer_to_specialist);
         business executors (marketing budget, field reps, physician
         education, payer negotiation, screening campaign, center
         partnership); approval-queue CRUD; execute_option_steps() for
         playbooks; RISK_TIERS policy; rejection memory (30-day no-re-propose);
         value metrics; SMTP email (real if configured, else simulated+logged).
   WHY : separation of proposal and execution is the safety model.

 agent_watchdog.py
   WHAT: rule-based reflex layer that runs by itself on every app start (and
         from scheduler.py): 1) HIGH-severity side effects with no follow-up,
         2) denied claims not yet escalated (highest $ first), 3) diagnosed-
         but-untreated epilepsy patients. Max 5 proposals/category/sweep.
   WHY : instant, deterministic detection that shouldn't wait for a human to
         open a page — and the entry point for risk-tiered autonomy.

 app.py
   WHAT: Streamlit UI. SIGMA brand (inline SVG logo: Σ badge, EEG pulse,
         medical cross; gradient wordmark). 8 pages; reusable dashboard
         machinery (§4.0); render_ai_panel() opportunity cards with
         approve/queue-and-dismiss behavior; Action Center. A self-heal
         guard at the top reloads stale in-memory modules after code updates
         (Streamlit hot-reloads app.py but not imported modules).

 scheduler.py
   WHAT: python scheduler.py (daily 08:00) or --once. Runs watchdog sweep
         (auto_execute=True) + Claude deep scan; prints an executive report.

 test_connection.py
   WHAT: standalone pre-flight: lists ODBC drivers → connects → lists tables →
         row counts → creates agent tables. Run BEFORE first app start.

 3. DATA MODEL (REAL SSMS TABLES — names contain spaces, always [bracketed])
───────────────────────────────────────────────────────────────────────────────
 DIMENSIONS
   [PTNT DIM]   PATIENT_ID, PATIENT_BIRTH_YEAR, PATIENT_GENDER (1=M,2=F),
                PATIENT_ZIP3, PATIENT_STATE   (18 US states, 2-letter codes)
   [DRUG DIM]   DRUG_ID, NDC11, DRUG_NAME, BGI (B/G), BB_USC_CODE/NAME
                (therapeutic class), MANUFACTURER, strength/form/package
   [DX DIM]     DIAGNOSIS_CODE (ICD-10) → DIAGNOSIS_DESCRIPTION
   [PHSY DIM]   PRACTITIONER_ID, names, CITY, STATE, SPECIALTY, NPI
   [PLAN]       PLAN_ID, PLAN_NAME, PLAN_TYPE, NATIONAL_INSURER_NAME, PBM
   [PX DIM]     PROCEDURE_CODE → PROCEDURE_DESCRIPTION
   [PRC ROLES]  practitioner role lookup

 FACTS / CLAIMS
   [DX CLM]     diagnosis events (PATIENT_ID, SERVICE_DATE, DIAGNOSIS_CODE)
   [RX CLM]     prescription fills (PATIENT_PAY, PLAN_PAY, RX_FILL_DATE,
                DRUG_ID, PRACTITIONER_ID, PLAN_ID) — REVENUE = PLAN_PAY+PATIENT_PAY
   [PX  CLM]    procedures/visits (TWO spaces in the name!)
   [PTNT ACT]   activity flags per year/quarter
   [PTNT_MPD]   Medicare Part D phases & spend
   [NEW_PTNT]   newly captured patients
   Fact_Sx                  side-effect reports + severity (Low/Medium/High)
   Fact_Drug_Switches       from_drug_id → to_drug_id + reason
                            ('Cost','Side Effect','Effectiveness','Insurance')
   Fact_Insurance_Claims    payer, region, amounts, status, denial reason,
                            prior_auth_days
   Fact_Marketing           campaign spend by region/drug

 AGENT OPERATIONAL TABLES (auto-created; all timestamps UTC)
   Agent_Pending_Actions · Agent_Business_Actions · Agent_Appointments ·
   Agent_Notifications · Agent_Audit_Log · Agent_Chat_History

 KEY DERIVED DEFINITIONS (shared by SQL and the AI)
   SEIZURE COHORT       = patients with an epilepsy (G40.*) or seizure-symptom
                          (R56.*) diagnosis OR an anti-seizure prescription —
                          this (not the raw patient dimension) is what every
                          executive KPI counts
   Confirmed epilepsy   = any cohort G40.* code in [DX CLM]
   Contexts (severity)  = seizure duration encoded in the code:
                          EPILEPTIC (<2 min) · PROLONGED (2–5 min) ·
                          STATUS EPILEPTICUS (5+ min)
   Age bands            = 0-1 · 2-11 · 12-17 · 18+ (from PATIENT_BIRTH_YEAR)
   Untreated            = confirmed epilepsy, but NO [RX CLM] fill for an
                          anti-seizure class (BB_USC_CODE 72110/72120/72130/72140)
   Undiagnosed suspect  = ONLY symptom codes (R56.9/R56.00/R56.01), no G40
   Active/adherent      = fill within 120 days of the data's max fill date
                          (or of the selected date window's end)
   OUR revenue at risk  = switches AWAY from MANUFACTURER='EISAI' drugs

 NOTE ON MANUFACTURERS: the manufacturer 'UCB' was removed from the database
 (relabeled to 'OTHERS'); its brands remain as competitor drugs. "Us" = EISAI.

───────────────────────────────────────────────────────────────────────────────
 5. THE AGENTIC FRAMEWORK — HOW "SUGGEST → APPROVE → EXECUTE" WORKS
───────────────────────────────────────────────────────────────────────────────

 5.1 Opportunity Cards (multi-option recommendations)
   Every page's live, FILTER-AWARE data → generate_page_insight() → Claude
   returns STRICT JSON: headline, number-backed insights[], risks[],
   business_opportunity, opportunities[] — each with a finding,
   value_at_stake, and 2–3 GENUINELY different options (label, approach,
   effort/cost, timeframe, confidence, trade-off reason, expected impact,
   estimated_value_usd, and executable steps[]).
   UX RULE: once an option is Approved or Queued, the WHOLE card disappears
   from the page (the alternatives were routes to the same finding); a toast
   points to the Action Center. Fresh "Generate" clears dismissals.
   WHY multi-option: the AI is the analyst; the BUSINESS stays the decision-
   maker.

 5.2 Two action categories
   PATIENT-LEVEL: schedule_appointment · send_notification ·
     order_diagnostic_test · change_prescription · escalate_claim ·
     enroll_support_program · refer_to_specialist
   BUSINESS-LEVEL (team-routed): reallocate_marketing_budget→marketing ·
     deploy_field_reps→field-force · launch_physician_education→med-affairs ·
     initiate_payer_negotiation→market-access · launch_screening_campaign→
     med-affairs · partner_with_center→commercial
   WHY the split: marketing/payer findings shouldn't produce patient spam;
   patient urgency shouldn't produce vague strategy advice.

 5.3 Playbooks — an option's steps[] may hold 2–4 ordered steps mixing
   categories; approval runs them in order, each with its own record,
   notification and audit row.

 5.4 Approval workflow (the safety model)
   AI proposes → row in Agent_Pending_Actions / Agent_Business_Actions
   (duplicate guard + 30-day rejection memory) → human decides (page card or
   Action Center) → execute → real records + notification (SMTP or simulated)
   + audit entry, all UTC-stamped.

 5.5 The chat agent loop — messages → Claude (tools) → tool_use? → run tool →
   append result → repeat (≤12) → final text. Guards: SELECT-only, keyword
   blocklist, 200-row cap, T-SQL dialect awareness, readable API-error
   handling (auth / rate limit / network).

 5.6 Autonomy — scheduler.py runs the same mission daily at 08:00; humans
   arrive to a prioritised, pre-analysed queue.

 5.7 Claude API usage — model from .env (default claude-opus-4-8); adaptive
   thinking; structured outputs (json_schema) for insights; strict tool
   schemas; key only from .env.

───────────────────────────────────────────────────────────────────────────────
 8A. AUTONOMY LAYER (IMPLEMENTED)
───────────────────────────────────────────────────────────────────────────────
 • AUTONOMOUS WATCHDOG (agent_watchdog.py) — runs on every app start and in
   the scheduler: 1) HIGH-severity side effects with no follow-up, 2) denied
   claims not yet escalated ($ desc), 3) diagnosed-but-untreated patients.
   Max 5 proposals/category/sweep, duplicate-aware.
 • RISK-TIERED AUTO-EXECUTION (actions.RISK_TIERS + sidebar toggle)
     LOW  → auto-executed as "Autopilot" when Autonomous Mode is ON:
            send_notification, schedule_appointment, escalate_claim,
            enroll_support_program
     HIGH → ALWAYS human-approved: order_diagnostic_test, change_prescription,
            refer_to_specialist, and ALL business actions.
 • STICKY TOGGLES — Autonomous Mode & Auto-generate Insights persist across
   page navigation (backed by non-widget session keys).
 • LEARNING FROM REJECTIONS — rejected actions are not re-proposed for 30
   days; recent rejections are injected into every insight/chat call.
 • VALUE LOOP — every proposal carries estimated_value_usd; Action Center
   shows Value Captured / Pending / Approval Rate; queues sort by value.
 • AGENT STATUS STRIP — every page shows autonomy state, watchdog detections,
   pending approvals ($) and value captured.


───────────────────────────────────────────────────────────────────────────────
 8B. OPERATIONS NOTES (RUNTIME BEHAVIOURS WORTH KNOWING)
───────────────────────────────────────────────────────────────────────────────
 • SELF-HEAL IMPORTS — Streamlit hot-reloads app.py but keeps old imported
   modules in memory; a guard at the top of app.py detects a stale backend/db
   (marker checks) and importlib.reload()s them — a browser refresh fixes
   "module has no attribute ..." errors without restarting the server.
 • REFRESH FROM SSMS — sidebar button clears cached insights and re-runs the
   watchdog; new rows added in SSMS appear immediately.
 • DATE ANCHORING — the data ends in 2025; "active/adherent" anchors to the
   max fill date (or the selected window's end), not to today.
 • uvicorn is pinned <0.44 (websocket reconnect race with Streamlit).
 • Insight cards and their dismissals are session-scoped; approved/queued
